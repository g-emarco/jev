## 1. Agent Development Kit (ADK)
- What: open-source framework to build, debug and deploy agents. Languages: Python, TypeScript, Go, Java, Kotlin. ADK 2.0 adds graph workflows that mix deterministic code with LLM reasoning. Other features: sequential/loop/parallel orchestration, agent routing, sessions/memory/artifacts, eval, web UI and visual builder, Agents CLI, live audio/video. Model-agnostic (Gemini, Gemma, Claude, OpenAI, Ollama, vLLM, LiteLLM). Source: https://adk.dev/
- Production use cases: multi-agent workflows with deterministic control paths; agents deployed to Agent Runtime, Cloud Run or GKE. Source: https://adk.dev/
- Use when: you are on or moving to Google Cloud and want first-party deploy, trace and registry integration; you want a multi-language SDK; you want graph-style workflows (https://adk.dev/).
- Do NOT use / prefer LangChain/LangGraph when: you already have a LangGraph codebase. Agent Runtime also hosts LangChain and LangGraph agents, so migrating is not required (https://docs.cloud.google.com/vertex-ai/generative-ai/docs/agent-engine/overview). Ecosystem size and maturity comparison with LangGraph: UNVERIFIED.
- Ops: ADK 2.0 graph workflows are described as "new". Maturity and breaking-change risk: UNVERIFIED.

## 2. Agent Runtime (formerly Vertex AI Agent Engine, per inference)
- What: managed, serverless environment for deploying and scaling agents. Features: five deployment methods plus Terraform; agent identity, service accounts, API keys, OAuth clients; Cloud Trace, Cloud Logging and metrics with alerts; bidirectional streaming; Private Service Connect interfaces for VPC; routing via Agent Gateway. Frameworks: LangChain, LangGraph, LlamaIndex, A2A, ADK, AG2, custom. Source: https://docs.cloud.google.com/vertex-ai/generative-ai/docs/agent-engine/overview
- Sessions: store user-agent state, access controllable with IAM Conditions. Memory Bank: long-term memory generated by LLMs from sessions. Same source.
- Security: supports VPC Service Controls, CMEK, data residency at rest, HIPAA, Access Transparency/Approval. Same source.
- Another page describes sub-second cold starts and support for long-running agents: https://docs.cloud.google.com/agent-builder/pricing (marketing-style page, no prices on it).
- Use when: you want minimal infra work and enterprise compliance controls (https://adk.dev/deploy/).
- Do NOT use when: you need container-level control, open-model hosting (use GKE), or non-GCP/offline hosting (https://adk.dev/deploy/).
- Pricing: no numeric prices found. The pages fetched link to Agent Platform pricing, and the cloud.google.com/vertex-ai/pricing page was too large to fetch. Numbers: UNVERIFIED.
- Quotas/limits: no numeric limits found in the docs fetched (overview and quotas pages). UNVERIFIED.
- Caveat: ADK confirmation (HITL) is not supported with VertexAiSessionService (https://adk.dev/tools-custom/confirmation/).

## 3. A2A protocol
- What: open standard for agent-to-agent communication across frameworks and vendors. Created by Google and donated to the Linux Foundation. Technical Steering Committee includes AWS, Cisco, Google, IBM Research, Microsoft, Salesforce, SAP and ServiceNow. Apache 2.0. SDKs: Python, JS, .NET, Java, Go, Rust. A "v1.0" page exists. Agents stay opaque (no shared memory or tools). Source: https://a2a-protocol.org/latest/
- Relation to MCP: complementary. MCP is agent-to-tool; A2A is agent-to-agent. Same source.
- ADK exposes and consumes A2A agents (Python, Go, Java; Kotlin consume) - https://adk.dev/
- Use when: cross-team or cross-vendor agents (for example LangGraph, CrewAI and ADK together) must interoperate. Not needed for a single-framework, single-process system (inference, no source).
- Ops: latency and auth overhead of remote hops: UNVERIFIED.

## 4. Cloud Run / GKE deployment
- Agent Runtime is the most hands-off option. Cloud Run runs the agent as a container (FastAPI plus Dockerfile example) with managed scaling. GKE gives the most control, suits customized setups and open models. Any container environment also works. Source: https://adk.dev/deploy/
- Cloud deployments get built-in auth and Cloud Trace without code changes (https://adk.dev/).
- Pricing/limits (Cloud Run timeouts, GKE costs): UNVERIFIED.

## 5. Observability (Cloud Trace)
- Setup: `adk deploy agent_engine --otel_to_cloud` (Python), `adkgo web -otel_to_cloud` (Go), `AdkApp(enable_tracing=True)`, or OpenTelemetry exporters (Python, TypeScript, Go). Spans: invoke_agent, generate_content, call_llm, execute_tool. Viewed in Trace Explorer. Source: https://adk.dev/integrations/cloud-trace/
- Caveat: payload capture is off by default on Agent Runtime deploy (`ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false`, placeholders instead of prompts/tool args). On Cloud Run/GKE you must set it yourself. Same source.
- Other options (BigQuery Agent Analytics, AgentOps, Phoenix, MLflow) appear only in a skill description, not in a fetched doc: UNVERIFIED. LangSmith comparison: UNVERIFIED.

## 6. Human-in-the-loop
- Tool confirmation: boolean (`require_confirmation`), dynamic (function on args), and advanced (`request_confirmation` with hint and payload). Remote responses via FunctionResponse named `adk_request_confirmation`. Web UI dialog. Source: https://adk.dev/tools-custom/confirmation/
- Status: Experimental. Needs Python 1.14.0+, TypeScript 0.2.0+, Go 0.3.0+, Kotlin 0.1.0+. Not supported with DatabaseSessionService or VertexAiSessionService. Same source.
- Versus LangGraph interrupts/checkpointers: LangGraph's HITL comparison is UNVERIFIED (not researched here). Given the limitations above, check session-service compatibility before relying on it.

## 7. Guardrails
- Layers: agent vs user identity; in-tool policy checks via Tool Context; Before Tool Callback; runner-level plugins (Gemini-as-a-Judge, Model Armor plugin shipped with ADK, PII Redaction plugin); Gemini content filters; sandboxed code execution; VPC-SC. Source: https://adk.dev/safety/
- Page says identity and perimeters are coarse, so tool-level guardrails are needed. Same source.
- Model Armor pricing/latency: UNVERIFIED.

## 8. Agent Registry / Gemini Enterprise
- Agent Registry: central catalog to store, discover and govern agents, MCP servers, skills, endpoints. Works with A2A and MCP. Resources: Agent, McpServer, Endpoint, Skill, SkillRevision, Publisher. Pairs with Agent Identity (verifiable principals) and Agent Gateway (runtime enforcement of IAM and content security policies). Registration automatic or manual; ADK integration; audit logs. Source: https://docs.cloud.google.com/agent-registry/overview
- The page ties it to the Gemini Enterprise Agent Platform; it does not describe a direct relationship with the Gemini Enterprise app. Release status (preview/GA) not stated; page last updated 2026-10-13. Same source.
- Publishing ADK/A2A agents to Gemini Enterprise via `agents-cli publish`: mentioned only in an installed skill description, UNVERIFIED in official docs.
- Use when: many teams/agents need governance and discovery. Overkill for one or two agents (inference).
